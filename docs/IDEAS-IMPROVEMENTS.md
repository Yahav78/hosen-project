# רעיונות לשיפור — חוסן (HOSEN)

מסמך זה מציע כיוונים לפיתוח המוצר והקוד, ללא התחייבות לביצוע. ניתן לבחור פריטים לפי עדיפות עסקית וטכנית.

---

## חוויית משתמש (UX/UI)

- **מצב חירום**: להציג זמן הפעלה, סוג טריגר (ידני / אודיו / משפחה), והוראות מקומיות אם קיים מיקום GPS.
- **עקביות שפה**: לוודא שכל המסכים (כולל אזהרות `alert`, פאנל אדמין, מפת Leaflet) עוברים דרך i18n ו־RTL.
- **משוב ויזואלי**: טוסטים במקום `alert`, מצבי טעינה/skeleton ברשימות, ואישור מחיקה עקבי (מודל במקום `confirm`).
- **נגישות**: ניגודיות צבעים בכפתורים, תוויות לשדות טופס, ניווט מקלדת בסרגל הכלים, ותמיכה ב־`prefers-reduced-motion` לאנימציות רקע חירום.
טיפול בבעיות התחברות לפעמים לא מתחבר בפעם הראשונה
---

## מוצר ותוכן


- **היסטוריית אירועים**: לוג של הפעלות חירום (מי, מתי, סוג) לקריאה בממשק ובאדמין — שימושי לבירור אחרי אירוע.
- **התראות דחיפה / SMS**: שכבה חיצונית (Twilio, Firebase Cloud Messaging) להז alerts כשמישהו מכריז על חירום או כשנכנס ל"בסכנה".
- **מפת מוקדי עזרה**: שכבת נקודות עניין (בתי חולים, תחנות משטרה) ממקורות ציבוריים או OSM.

---

## אמינות ובטיחות

- **אימות קלט**: סכימות (למשל Zod) בצד השרת לכל גוף בקשה; הגבלת גודל קבצים והרחבות מותרות ב־Vault.
- **Rate limiting**: הגנה על `/api/auth/login` ועל נתיבים ציבוריים מפני brute force.
- **Secrets**: וידוא ש־`.env` לא נכנס ל־git; רוטציה של `JWT_SECRET` בתיעוד פריסה.
- **HTTPS**: בפרודקשן — TLS מלא בין לקוח לשרת ולמסד.

---

## ארכיטקטורה וקוד

- **מונורפו / סקריפטים**: סקריפט `npm run dev` בשורש שמריץ במקביל client + server (למשל `concurrently`).
- **שכבת API במסך הלקוח**: ריכוז קריאות `axios` במודול אחד (`services/api.ts`) עם interceptors לטוקן וטיפול בשגיאות 401.
- **טיפוסים משותפים**: ייצוא ממשקים מ־TypeScript מהשרת או חבילת `types` משותפת כדי לצמצם `any` בלקוח.
- **ביטול נקודות `/api/debug-*`**: להסיר או להגן בהרשאת אדמין בלבד בפרודקשן.
