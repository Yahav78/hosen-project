# תכנית עבודה ראשונית — פרויקט חוסן (HOSEN)  
## היבטי מדעי המחשב והנדסת תוכנה בלבד

מסמך זה מתאר את התפתחות המערכת מנקודת מבט הנדסית: ארכיטקטורה, שלבי שחרור, אבני דרך טכניות, מדדי הצלחה הניתנים למדידה בסביבת פיתוח/תפעול, וסיכונים הנדסיים.

---

## 1. תיאור קצר בהקשר הנדסי

המערכת בנויה כ**אפליקציית ווב מלאה (full-stack)**:

- **לקוח:** יישום SPA ב־React (TypeScript), ניווט מוגן, תמיכה בריבוי שפות (i18n), תקשורת בזמן אמת עם השרת (Socket.IO).
- **שרת:** API ב־Node.js ו־Express, אימות JWT, REST לניהול משתמשים, משפחה, מלאי, כספת מסמכים ועוד.
- **נתונים:** MongoDB עם Mongoose; מודלים יחסיים (משתמשים, הזמנות משפחה, פריטי מלאי, אירועי חירום וכו').
- **זמן אמת:** Socket.IO לעדכון סטטוס ולהפעלת פרוטוקול חירום ברמת החדר (משפחה).

תכנית השלבים להלן מתאימה להרחבה הדרגתית של יכולות אלו תוך שמירה על איכות תוכנה ובטיחות.

---

## 2. שלבי היישום: MVP / פיילוט / מהלך מדורג

### 2.1 MVP (Minimum Viable Product)

**מטרה הנדסית:** להוכיח זרימת קצה־לקצה יציבה — הרשמה/התחברות, פרופיל, ליבת דשבורד משפחתי, והפעלת חירום בסיסית עם רישום באחורה.

**בסיס טכני צפוי:**

| תחום | תוכן |
|------|------|
| אימות | JWT, מסלולי API מוגנים, בידוד שגיאות אימות |
| נתונים | סכמות Mongoose עקביות, אינדקסים על שדות חיפוש נפוצים (למשל אימייל) |
| לקוח | מסכים קריטיים, טיפול ב־401/ריענון פרופיל |
| זמן אמת | חיבור Socket, חדר משפחה, אירועי חירום וסטטוס |

**קריטריון “MVP סגור”:** הרצה מקומית/סביבת אינטגרציה עם זרימה מלאה ללא כשל קריטי בנתיבים העיקריים.

---

### 2.2 פיילוט (Pilot)

**מטרה הנדסית:** בחינת המערכת עם קבוצת משתמשים מוגבלת — עומס אמיתי, דפוסי שימוש, ותיקונים לפני הרחבה.

**הרחבות טיפוסיות לפיילוט:**

- ניטור בסיסי (לוגים מובנים, זיהוי שגיאות שרת).
- בדיקות אוטומטיות ליבה (יחידה/אינטגרציה לנתיבי API קריטיים).
- קיבוע גרסאות (`package-lock`), תיעוד משתני סביבה נדרשים.
- הערכת ביצועים ראשונית (זמן תגובה API, חיבורי Socket).

**קריטריון פיילוט:** יציבות מוגדרת (למשל זמינות ושיעור שגיאות 5xx מתחת לסף שנקבע מראש) לאורך תקופת הניסוי.

---

### 2.3 מהלך מדורג (Phased Rollout)

**מטרה הנדסית:** הוספת יכולות וקנה מידה בלי לשבור את המערכת הקיימת.

דוגמאות לשלבים עוקבים (סדר גמיש לפי עדיפות):

| שלב | תוכן הנדסי |
|-----|------------|
| א | שכבת שירותים בלקוח (מודול API מרכזי), צמצום כפילות קריאות |
| ב | אימות קלט בשרת (סכימות), הגבלת קצב (rate limiting) על נתיבי אימות |
| ג | הרחבת תיעוד API, טיפוסים משותפים או ייצוא טיפוסים מהשרת |
| ד | פריסה מבוקרת (staging/production), HTTPS, גיבויים למסד |
| ה | ניטור מתקדם, התראות על תקלות, בדיקות עומס נקודתיות |

כל שלב אמור להיות **ניתן לפריסה עצמאית** (feature flags או גרסאות API כשצריך).

---

## 3. אבני דרך מרכזיות (הנדסיות)

| אבן דרך | תיאור | תוצר מדיד |
|---------|--------|-----------|
| M1 | ארכיטקטורת לקוח–שרת–מסד פועלת בסביבת פיתוח | הרצה מקצה לקצה |
| M2 | מודל נתונים יציב + מיגרציות/תאימות לאחור לפי הצורך | סכמות מתועדות |
| M3 | אבטחת בסיס: סודות בסביבה, JWT, ללא דליפת `.env` | סקירת קונפיגורציה |
| M4 | זמן אמת אמין לסשנים קצרים ובינוניים | בדיקות עומס Socket בסיסיות |
| M5 | מוכנות לפרודקשן חלקית: HTTPS, לוגים, גיבוי DB | צ’ק־ליסט פריסה |
| M6 | איכות מתמשכת: בדיקות אוטומטיות ב־CI | ירוק בבנייה |

---

## 4. מדדי הצלחה (מובנים למדידה טכנית)

מדדים אלה מתאימים להצגה במסגרת קורס/פרויקט במדעי המחשב:

| מדד | הגדרה | דוגמת יעד (ניתן לכוון) |
|-----|--------|-------------------------|
| זמינות שרת | אחוז זמן שה־API מחזיר תגובה תקינה | > 99% בסביבת פיילוט |
| זמן תגובה API | p95 לנתיבים קריטיים | מתחת לסף שנקבע (למשל 300ms LAN) |
| שיעור שגיאות 5xx | יחס תגובות שרת כושלות | מתחת ל־1% בטווח ניסוי |
| כיסוי בדיקות | אחוז נתיבים/מודולים עם בדיקות אוטומטיות | עליה מדורגת לפי שלב |
| איכות קוד | ספירת אזהרות לינטר/בנייה נכשלת ב־CI | אפס שגיאות בבנייה |
| אבטחה בסיסית | אין endpoint רגיש ללא אימות; קבצים רגישים לא בקוד מקור | עמידה בסקירה סטטית |

## 5. סיכונים עיקריים והתמודדות הנדסית

| סיכון | השפעה | הפחתה |
|------|--------|--------|
| תלות במסד נתונים חיצוני | תקלות חיבור משביתות את האפליקציה | חיבור עם ניסיון חוזר, הודעות שגיאה ברורות, גיבויים |
| אימות וניהול טוקנים | חשיפה או תוקף לא תקין | JWT עם תוקף, HTTPS בפרודקשן, רוטציית סודות |
| עומס על Socket.IO | חיבורים נופלים או עיכוב בשידור | הגבלת גודל חדרים/אירועים, ניטור, scale-out עתידי |
| סכימות גמישות מדי ב־Mongo | נתונים לא עקביים | אימות קלט בשרת, אינדקסים ואילוצים בסכמה |
| סיכון אבטחת מידע (העלאות / קבצים) | דליפה או הרצת קבצים זדוניים | הגבלת גודל/סוג קובץ, נתיבי שמירה מבוקרים, הרשאות |
| חוב טכני | האטה בפיתוח | תכנון שלבים, ריפקטור מבוקר אחרי MVP |

---

## 6. סיכום

מסמך זה מספק **תכנית עבודה ראשונית** במונחים של הנדסת תוכנה: שלבי MVP, פיילוט ומהלך מדורג; אבני דרך הניתנות למעקב; מדדי הצלחה מדידים; וסיכונים עם כיווני הפחתה. ניתן להציג את הפרויקט בכך בתור מערכת מבוזרת לקוח–שרת עם נתונים וזמן אמת, תוך תכנון התפתחות מבוקרת.
